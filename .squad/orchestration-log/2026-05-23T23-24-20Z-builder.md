## Summary

Agent diagnosed and fixed an off-by-one error in ship availability display across two UI components. The simulation logic was correct; only the UI display required correction.

---

## Investigation

**Bug:** Ships showed up a turn after promised in the UI, despite simulation working correctly.

**Root Cause:** 
- `ShipInstance.available_turn` represents the turn when the delivery pipeline step runs
- Players plan BEFORE the pipeline — so a ship with `available_turn = N` is delivered during turn N but only usable during turn N+1's planning phase
- Both `ships_modal.gd` (line 83) and `dashboard_panel.gd` (line 77) displayed `available_turn` directly without the +1 offset

**Solution:** Display `available_turn + 1` in both UI locations, matching when the player can actually assign the ship.

---

## Implementation

**Files Modified:**
1. `src/game/ui/modals/ships_modal.gd` — Updated ship ready turn display
2. `src/game/ui/panels/dashboard_panel.gd` — Updated pending ship display

**Decision Rationale:**
- Formula `current_turn + build_turns - 1` is correct for pipeline semantics (unchanged)
- UI layer compensates for the semantic difference between "pipeline turn" and "player planning turn"
- Alternatives (changing formula or moving delivery) were more invasive
